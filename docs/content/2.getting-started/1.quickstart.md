Marrow has no graphical drag-and-drop canvas. The editing interface is a conversation: an operator describes a network, an autonomous vertical AI agent authors and validates the topology YAML, and the operator reviews the compiled interactive diagram.

Follow these steps to configure your agent, clone Marrow, and compile your first topology.

---

## Step 1: Use Any Vertical AI Agent of Your Choice

Marrow is designed to work with any vertical AI agent or autonomous coding assistant. You describe your network requirements in natural language; the agent handles schema authoring, icon lookups, and compiler verification.

Choose any vertical agent or coding environment of your choice:
- **Terminal CLI Agents**: [Claude Code](https://docs.anthropic.com/en/docs/agents-and-tools/claude-code/overview), [Aider](https://aider.chat), or terminal shell scripts.
- **Agentic IDEs & Extensions**: [Cursor](https://cursor.com), [Windsurf](https://codeium.com/windsurf), [Antigravity](https://antigravity.google/), [Cline](https://github.com/cline/cline), or [GitHub Copilot](https://github.com/features/copilot).
- **Autonomous Platforms & Open Lists**: [OpenHands](https://github.com/All-Hands-AI/OpenHands), [Devin](https://cognition.ai), or any assistant from curated registries like [Awesome AI Agents (e2b)](https://github.com/e2b-dev/awesome-ai-agents) and [Awesome LLM Agents](https://github.com/chenfei-ye/Awesome-LLM-Agents).

### How agents read Marrow

Marrow includes operational instructions in the repository root:
- **`AGENTS.md`**: Defines compiler modes, invariant rules, and command references.
- **`.agents/skills/marrow-topology/`**: Domain skill covering schema validation, icon queries, link semantics, and geometric collision checks.

When you open the Marrow repository in your vertical agent, it reads `AGENTS.md` automatically.

## Step 2: Clone Marrow and Run Setup

Marrow requires **Node.js 24 or newer**. It operates completely offline with zero database or external rendering servers.

### 1. Clone the repository

```bash
git clone https://github.com/raiz-toff/Marrow.git
cd Marrow
```

### 2. Run the setup script

Execute the interactive setup command:

```bash
npm run setup
```

The script runs six automated verification steps:
1. Validates Node.js version ($\ge 24$).
2. Installs workspace dependencies via `npm install`.
3. Compiles the TypeScript packages and the offline client runtime bundle.
4. Installs verified vendor icon packs (Cisco, Affinity, AWS, Azure, GCP).
5. Prompts for optional organization branding in `marrow.config.yaml`.
6. Compiles a test diagram end-to-end to verify the toolchain.

For headless CI/CD pipelines or container builds, use the non-interactive flag:

```bash
npm run setup -- --yes
```

## Step 3: Prompt Your Agent (or Author YAML)

Once your vertical agent is running inside the Marrow workspace, describe your network in plain language. The agent executes the **understand → author → validate → see** loop automatically.

### Example prompts for your agent

::code-group
```text [Data Center Fabric]
Create a 2-spine 4-leaf EVPN datacenter topology in input/dc-fabric.yaml.
Use Cisco Nexus 9000 switches with 100G routed uplinks between leaves and spines.
Add an about section documenting our maintenance window and runbook link.
Validate the schema and generate a snapshot PNG for review.
```

```text [Branch Office]
Read our branch router config snippet and create input/branch-office.yaml.
Group devices into an edge zone and LAN zone.
Connect the WAN router to an HA firewall pair, and link down to access switches.
Validate the file and fix any diagnostic warnings.
```

```text [Cloud Transit Gateway]
Generate an AWS transit gateway network connecting two VPCs (Production and Staging).
Use official AWS EC2, Transit Gateway, and VPC icons from the aws icon pack.
Set the layout density to standard and theme to dark.
```
::

### Authoring by hand

If authoring YAML directly without an agent, create `input/network.yaml`:

```yaml [input/network.yaml]
marrow: 2
name: Core Spine-Leaf Fabric
author: NetOps Architecture Team
theme: dark
density: standard

# Documentation modal and watermark attribution
about:
  Architecture: 5-stage Clos data center fabric with EVPN-VXLAN overlay.
  Maintenance: Bi-weekly maintenance window Tuesdays 02:00-04:00 UTC.
  Runbook: https://wiki.internal.net/runbooks/spine-leaf-failover

zones:
  - id: dc-fabric
    name: Primary Fabric
    accent: "#3b82f6"

devices:
  - id: spine-01
    name: Spine Switch 1
    icon: cisco/switches/layer-3-switch
    tier: core
    zone: dc-fabric
    mgmt_ip: 10.0.0.1

  - id: spine-02
    name: Spine Switch 2
    icon: cisco/switches/layer-3-switch
    tier: core
    zone: dc-fabric
    ha_pair_with: spine-01
    mgmt_ip: 10.0.0.2

  - id: leaf-01
    name: Leaf Switch 1
    icon: cisco/switches/workgroup-switch
    tier: distribution
    zone: dc-fabric
    mgmt_ip: 10.0.1.1
    interfaces:
      - name: Eth1/1
        description: Uplink to Spine 1
      - name: Eth1/2
        description: Uplink to Spine 2

links:
  - from: spine-01:Eth1/1
    to: leaf-01:Eth1/1
    mode: routed
    speed: 100G
    protocol: ebgp

  - from: spine-02:Eth1/1
    to: leaf-01:Eth1/2
    mode: routed
    speed: 100G
    protocol: ebgp
```

## Step 4: Discover Vendor Icons

Never guess icon identifiers. Search the catalog of ~2,850 verified vendor icons before defining devices:

```bash
# Search for generic switch and router types
npm run icons search switch router firewall

# Search specific vendor hardware
npm run icons search "cisco nexus" "layer 3 switch"
```

Icon identifiers follow `<pack>/<category>/<name>`.

| Vendor Pack | Example Identifier | Device Type |
| :--- | :--- | :--- |
| `cisco` | `cisco/switches/layer-3-switch` | Layer 3 Core Switch |
| `cisco` | `cisco/security/firewall` | Security Appliance |
| `affinity` | `affinity/tile/router` | WAN Edge Router |
| `affinity` | `affinity/tile/server` | Compute Server |
| `aws` | `aws/compute/ec2` | EC2 Virtual Machine |

## Step 5: Validate and Compile

Marrow enforces strict schema verification and geometric collision detection before compiling HTML.

### 1. Validate schema and layout

```bash
npm run validate input/network.yaml
```

The validator checks:
- Strict schema syntax and type constraints.
- Uniqueness of device identifiers.
- Resolution of link ports and device endpoints.
- HA pairing constraints (`ha_pair_with`).
- Collision gates to guarantee zero overlapping nodes or zones.

To produce machine-readable JSON for agents, add `--json`:

```bash
npm run validate input/network.yaml --json
```

### 2. Verify visual output (`snapshot`)

Generate a headless Chromium rendering to inspect visual hierarchy and edge routing:

```bash
npm run snapshot input/network.yaml -o output/network.png
```

Vision-enabled agents inspect this image to confirm tier alignment, zone bounds, and label placement.

### 3. Compile standalone HTML

Compile the final production diagram:

```bash
npm run build input/network.yaml -o dist/network.html
```

The compiled file (`dist/network.html`) is 100% self-contained. It contains inlined SVG icons, theme styles, and the interactive pan/zoom canvas client. It opens offline without network access:

```bash
open dist/network.html
```

## Step 6: Live Development Preview

During active authoring, start the hot-reloading development preview server:

```bash
npm run dev -- input/network.yaml
```

Open `http://127.0.0.1:5200` in your browser. Every change saved to `input/network.yaml` updates the canvas instantly over a local WebSocket.

## Step 7: Essential Customizations

### About This Diagram Modal

Define an `about:` dictionary in your topology YAML. The compiled diagram renders an **About this diagram** button in the command bar:

```yaml
about:
  Topology: Spine-Leaf EVPN Data Center Fabric
  Owner: NetOps Architecture Team
  Contact: netops@example.com
```

Clicking the button opens an engineering document dialog showing your custom markdown text alongside Marrow's watermark credit.

### Embedding and Dashboard Display Modes

Marrow supports iframe embedding into monitoring dashboards, internal wikis, and portal pages. Use URL hash flags or HTML attributes:

| Query / Hash Flag | HTML Dataset Attribute | Effect |
| :--- | :--- | :--- |
| `#embed=true` | `data-chrome="minimal"` | Strips command bar, status bar, and frame padding; stage fills container. |
| `#controls=off` | `data-controls="off"` | Hides zoom, pan, and reset canvas controls. |
| `#watermark=off` | `data-watermark="off"` | Hides the watermark badge for white-label dashboard integrations. |

Example iframe embedding code:

```html
<iframe
  src="network.html#embed=true&controls=off"
  width="100%"
  height="600px"
  style="border: 1px solid #27272a; border-radius: 8px;"
/>
```

### Layout Density Presets

Adjust node sizing and layout compactness with the `density:` setting:

```yaml
density: compact   # 48px nodes, tight spacing. Optimal for 500+ device campus networks.
density: standard  # 64px nodes, 48px gap (default).
density: spacious  # 80px nodes, 64px gap. Optimal for executive presentations.
```

### Engineering Title Blocks

Add a formal blueprint title block to your canvas with `title_block:`:

```yaml
title_block:
  title: Spine-Leaf EVPN Fabric
  drawing_number: DWG-NET-2026-004
  revision: Rev 3.2
  drawn_by: NetOps Architecture Team
  approved_by: Lead Network Architect
  date: 2026-10-19
```

## Common Diagnostic Codes

| Code | Meaning | Remediation |
| :--- | :--- | :--- |
| `MRW-E001` | Missing schema version | Declare `marrow: 2` at the top of the file. |
| `MRW-E010` | Unknown icon identifier | Run `npm run icons search <term>` and copy a verified ID. |
| `MRW-E020` | Unresolved device reference | Ensure endpoint IDs in `links:` match declared `id:` values in `devices:`. |
| `MRW-E031` | Invalid HA pair reference | `ha_pair_with` must reference a device in the same tier and zone. |
| `MRW-E040` | Geometric collision detected | Increase tier spacing or group devices into separate zones. |
