Diagnostic codes are **part of the public contract**. Agents and tests key off
them, so codes are never renumbered and never reused. `MRW-E***` is an error;
`MRW-W1**` is a warning.

Errors block the build. Warnings are advisory — usually worth fixing, never
blocking.

## Anatomy of a diagnostic

```
input/branch.yaml:14:11  error  MRW-E010  Unknown icon
     │            │  │     │       │         │
     file         │  col   │       code      title
                  line     severity

  13 │     name: Edge Router
  14 │     icon: affinity/tile/rooter
     │           ^^^^^^^^^^^^^^^^^^^^          ← snippet with the exact span
  15 │     tier: edge

  hint: search for a real id — marrow icons search rooter
  did you mean: affinity/tile/router · affinity/symbol/router · cisco/routers/router
```

Every diagnostic carries a code, a YAML path, a line and column, a source
snippet, a fix hint, and — where it makes sense — ranked did-you-mean
suggestions. `--json` gives you all of that as structured data.

::alert{type="info"}
Use the suggestions. They're ranked by edit distance against the real
catalog, so the first one is right far more often than a guess is.
::

## Errors

| Code | Title | Usual cause and fix |
| --- | --- | --- |
| :badge[MRW-E001]{type="danger"} | YAML syntax error | Malformed YAML — indentation, an unclosed quote, a stray tab. Fix at the reported line |
| :badge[MRW-E002]{type="danger"} | Document root must be a mapping | The file starts with a list or a scalar. The top level is a mapping with `marrow:`, `name:`, `devices:` |
| :badge[MRW-E003]{type="danger"} | Missing marrow version | Add `marrow: 2` as the first key |
| :badge[MRW-E004]{type="danger"} | Unsupported marrow version | Only the integer `2` is supported. `marrow: "2"` (a string) also trips this |
| :badge[MRW-E005]{type="danger"} | Unknown key | A typo (`teir:` for `tier:`) or a v1 key with no v2 equivalent. Prefix with `x-` to keep it private |
| :badge[MRW-E006]{type="danger"} | Invalid type | A string where a list belongs, a list where a mapping belongs |
| :badge[MRW-E007]{type="danger"} | Missing required field | A device without `id` or `icon`; a link without `from` or `to`; a zone without `id` |
| :badge[MRW-E008]{type="danger"} | Duplicate identifier | Two devices (or two zones) sharing an `id` |
| :badge[MRW-E009]{type="danger"} | Unknown device reference | A link endpoint, `hero`, or `ha_pair_with` naming a device that doesn't exist |
| :badge[MRW-E010]{type="danger"} | Unknown icon | The icon id isn't in the catalog — **or the pack isn't installed**. Suggestions are ranked; `marrow icons fetch <pack>` if it's aws/azure/gcp |
| :badge[MRW-E011]{type="danger"} | Invalid value | Outside the allowed set — a `tier` that isn't one of the six, a `speed` that isn't on the list, a `vlan` outside 1–4094 |
| :badge[MRW-E012]{type="danger"} | Invalid identifier | An id that isn't kebab-case `[a-z0-9._-]` starting with a letter or digit |
| :badge[MRW-E013]{type="danger"} | Unknown zone reference | A device's `zone`, or a zone's `parent`, naming a zone that isn't declared |
| :badge[MRW-E014]{type="danger"} | Invalid link endpoint | A malformed `from`/`to`. Format is `device-id` or `device-id:Port`; only the first colon splits |
| :badge[MRW-E015]{type="danger"} | Unknown reference | A reference of another kind that can't be resolved |
| :badge[MRW-E016]{type="danger"} | Zone hierarchy cycle | Zone `parent` links form a loop — A parents B parents A |
| :badge[MRW-E017]{type="danger"} | Internal validator error | A bug. Please [file an issue](https://github.com/raiz-toff/Marrow/issues) with the file that triggered it |

## Warnings

| Code | Title | What it means |
| --- | --- | --- |
| :badge[MRW-W101]{type="warning"} | Port used by multiple links | The same `device:Port` appears on more than one link. Usually copy-paste; occasionally a genuine shared physical port |
| :badge[MRW-W102]{type="warning"} | Empty zone | A declared zone with no devices. It renders as an empty panel — populate it or delete it |
| :badge[MRW-W103]{type="warning"} | Isolated device | A device with no links. Fine for a standalone appliance; usually a missing link or a typo'd endpoint |
| :badge[MRW-W104]{type="warning"} | Self-link | A link whose `from` and `to` are the same device |

## Machine-readable output

```bash
npm run marrow -- validate input/branch.yaml --json
```

Returns a report with per-file diagnostics: code, severity, message, YAML path,
line, column, snippet, hint, and suggestions. This is the interface for agents
and CI. Exit code is still `1` when there are errors, so it gates a pipeline
without parsing anything.

## Geometry defects are different

The `MRW` registry covers the **schema**. Layout problems are caught later by
the geometry linter, which has its own levels:

| Level | Behavior |
| --- | --- |
| **L1** | Fails the build — node overlap, edges through node interiors, endpoints not touching their node, port-chip overlap |
| **L2** | Auto-repaired |
| **L3** | Advisory — excessive crossings, extreme aspect ratio |

See [How layout is chosen](/guides/layout#the-geometry-linter).
