---
title: marrow.config.yaml
description: Global configuration — the settings that are identical across every diagram you build.
---

One file at the repo root holds everything static across *every* diagram.
Topology files describe a network; this file describes who it belongs to.

```yaml title="marrow.config.yaml"
brand:
  name: Marrow
  note: Proprietary & Confidential
  logo: brand/logo.svg
  link: https://marrow.network
  github: https://github.com/marrow-net/marrow
```

## `brand`

| Key | Type | Notes |
| --- | --- | --- |
| `name` | string | Shown beside the logo in the sidebar footer, the inspector drawer, and the top brand strip |
| `note` | string | Footer line — e.g. a classification banner. `""` means no line |
| `logo` | path | Relative to this file. **A path, never a URL** |
| `link` | http(s) URL | The logo and name link here |
| `github` | http(s) URL | Small source mark beside the brand |

Delete a key, or leave it blank, to fall back to Marrow's own mark.

### Logo handling

| Extension | Embedding |
| --- | --- |
| `.svg` | Inlined as markup. Use `fill="currentColor"` so it follows the theme |
| `.png` `.jpg` `.webp` `.gif` | Embedded as a `data:` URI |

Height is clamped in the chrome (14–20 px by position), so source size doesn't
matter.

Markup is sanitized before inlining: `<script>`, `<iframe>`, `<object>`,
`<embed>`, `<link>`, `<meta>`, inline event handlers, and any URL that would
reach outside the document are all removed. Problems are reported, not
swallowed. This is what keeps the offline guarantee true.

### Links are not loads

`link` and `github` are http(s)-only **hyperlinks**. Nothing is fetched when a
diagram opens; following one is an explicit reader action. Diagrams still
render fully offline.

## `theme`

Override the theme tokens: the palette, the status colours, and link stroke
widths and dash patterns. Both the SVG and canvas renderers read them from the
same CSS custom properties, so one override reaches both.

```yaml title="marrow.config.yaml"
theme:
  dark:
    bg: "#090d16"
    bg_raise: "#11151f"
    accent: "#3b82f6"
    accent_ink: "#ffffff"
    up: "#22c55e"
    status:              # status colours may also be nested
      down: "#ef4444"
  light:
    bg: "#ffffff"
    accent: "#2563eb"
  links:
    width_default: 1.5
    width_10g: 2.5
    width_40g: 4.0
    width_trunk: 3.0
    width_slot: 1.0
    width_stack: 5.0
    dash_tunnel: "9 6"
    dash_peering: "1.5 5"
    dash_degraded: "14 7"
    dash_planned: "2 7"
```

| Key | Type | Notes |
| --- | --- | --- |
| `dark` | map | Palette and status colours for the dark scheme (the `:root` defaults) — see the table below |
| `light` | map | The same keys for the light scheme (`:root[data-theme="light"]`) |
| `links` | map | All values in **px**. Widths (positive numbers): `width_default`, `width_10g`, `width_40g`, `width_trunk`, `width_slot`, `width_stack`. Dash patterns (a `"9 6"` string or a `[9, 6]` list of px runs): `dash_tunnel`, `dash_peering`, `dash_degraded`, `dash_planned`, `dash_flow`. camelCase spellings (`width10g`, `dashTunnel`) and the older `default_stroke` / `ten_g_stroke` / `forty_g_stroke` / `trunk_stroke` / `slot_stroke` / `stack_stroke` aliases are accepted. A dash whose every value is below 1 warns as a legacy normalized value |

### Palette and status keys

Every key is accepted in `snake_case` (shown) or camelCase (`bg_raise` or
`bgRaise`). The chrome is the interface around the diagram: sidebar, toolbars,
drawers and dialogs.

| Config key | CSS variable | What it paints |
| --- | --- | --- |
| `bg` | `--bg` | The diagram canvas; the halo behind labels and pills |
| `bg_raise` | `--bg-raise` | Page background behind the chrome; hovered and active controls |
| `panel` | `--panel` | The main card holding the canvas; drawers, popovers and menus |
| `line` | `--line` | Borders and dividers |
| `line_strong` | `--line-strong` | Emphasised borders: link-label pills, port labels, scrollbars |
| `ink` | `--ink` | Primary text and node labels |
| `ink_dim` | `--ink-dim` | Secondary text, icon fallbacks, glyphs on link chips |
| `ink_faint` | `--ink-faint` | Tertiary text: placeholders, captions, keyboard hints |
| `chip` | `--chip` | Fill of the node icon chip |
| `chip_line` | `--chip-line` | Outline of the node icon chip |
| `grid_dot` | `--grid-dot` | The canvas dot grid |
| `accent` | `--m-accent` | Selection, traced paths, animated flow, switches, badges |
| `accent_ink` | `--m-accent-ink` | Text on an accent fill (badge counts) |
| `ring` | `--ring` | Keyboard focus outline |
| `zone` | `--zone` | Zone tint and label when the zone declares no colour |
| `edge` | `--edge` | Default link stroke |
| `sidebar` | `--sidebar` | Sidebar background |
| `sidebar_fg` | `--sidebar-fg` | Sidebar text |
| `sidebar_accent` | `--sidebar-accent` | Hovered and active sidebar rows |
| `sidebar_border` | `--sidebar-border` | Sidebar edge and group rules |
| `shadow` | `--shadow` | Shadow under floating chrome — a CSS `box-shadow` list, not a colour |
| `shadow_sm` | `--shadow-sm` | Small shadow under toolbar buttons and tabs — a `box-shadow` list |
| `up` | `--up` | Status colour: up pills, dots and legend |
| `down` | `--down` | Status colour: down pills and dots; links whose status is down |
| `degraded` | `--degraded` | Status colour: degraded pills and dots; degraded links |
| `planned` | `--planned` | Status colour: planned pills and dots; planned links |
| `unknown` | `--unknown` | Status colour: unknown or undeclared status (inventory dot) |
| `surface` | `--panel` | **Alias** of `panel` |
| `muted` | `--ink-dim` | **Alias** of `ink_dim` |
| `faint` | `--ink-faint` | **Alias** of `ink_faint` |

The five status keys may sit flat in `dark:` / `light:` or nested under
`status:`; when both are set, the nested one wins.

Any other key — including `accent_hover`, `accent_subtle`, `subtle` and
`admin_down`, which no theme token backs — warns and lists the supported keys.
It is never silently dropped.

Colour values accept hex, `rgb()`, `rgba()`, `hsl()`, `hsla()`, `oklch()`,
`lab()`, `color()`, `color-mix()`, `var()` and named colours
(`SAFE_COLOR_REGEX`). `shadow` / `shadow_sm` take a `box-shadow` list and
reject `url()`. Values containing semicolons, braces, or angle brackets are
rejected with warnings.

## Watermark

A build-wide default for the attribution watermark drawn on every page. A
topology's own `watermark:` keys win over these.

```yaml
watermark:
  mode: subtle          # off | minimal | subtle | blueprint | full
  opacity: 0.08
  casing: uppercase     # uppercase | sentence | as-is
  font: mono            # mono | sans
```

| Key | Type | Notes |
| --- | --- | --- |
| `enabled` | boolean | `false` is the same as `mode: off` |
| `mode` | `off` \| `minimal` \| `subtle` \| `blueprint` \| `full` | How much of the title block is drawn |
| `opacity` | number | 0–1 |
| `casing` | `uppercase` \| `sentence` \| `as-is` | Letter casing of the watermark text |
| `font` | `mono` \| `sans` | Typeface family |

## `layout`

Default density preset and scale multiplier for every compiled diagram. Each value applies **only when the topology does not declare its own** `density` or `scale` in its header — a value written in the topology always wins. With neither set, diagrams use `standard` and `1.0`.

```yaml title="marrow.config.yaml"
layout:
  density: compact   # compact | standard | spacious (default: standard)
  scale: 1.0         # float between 0.4 and 2.5 (default: 1.0)
```

| Key | Type | Notes |
| --- | --- | --- |
| `density` | `compact` \| `standard` \| `spacious` | Used when the topology declares no `density`; `standard` if neither does. Scales node chips (48px / 64px / 80px), typography (10px / 12px / 14px), layer spacing, and port chips |
| `scale` | float 0.4–2.5 | Used when the topology declares no `scale`; `1.0` if neither does. Multiplies box padding, icon chip size, and layer spacing |

Edits to `marrow.config.yaml` hot-reload automatically in `marrow serve` without restarting the server.

## Pointing elsewhere

```bash
npm run marrow -- build    input/x.yaml --config brands/customer-a.yaml
npm run marrow -- serve    input        --config brands/customer-a.yaml
npm run marrow -- snapshot input/x.yaml --config brands/customer-a.yaml
```

This is the supported way to produce differently-branded outputs. There is no
per-topology branding — see [ADR-0003](/docs/decisions/0003-branding-is-global-only).

## Unknown keys

Unknown keys here **warn** rather than error (the opposite of topology files,
where they're fatal). `x-` prefixed keys are preserved and ignored.

<Callout type="info">
`npm run setup` writes this file interactively on a fresh clone — organization
name, footer note, theme, accent color, and a drop-in icon pack for your own
logos. Re-running setup never overwrites what you've edited.
</Callout>
