---
title: ADR-0015 — Modular UI chrome and embed modes
description: Enable zero-FOUC minimal chrome, inspector toggling, and kiosk display modes via URL query parameters, hash fragments, and declarative CSS.
---

**Status:** accepted

Compiled standalone HTML diagrams previously rendered desktop application chrome including topbar breadcrumbs, search docks, and sidebar slideouts. Marrow now supports zero-FOUC embed and kiosk modes through URL query parameters (`?chrome=minimal`, `?inspector=off`, `?minimap=off`, `?theme=light`) and hash fragments (`#embed=true`).

## Why

Embedding full diagram chrome into dashboards, documentation wikis, or monitoring displays caused visual clutter and wasted screen real estate.

Generating separate embed-specific HTML targets during the build was considered and rejected. Compiling distinct files per topology doubled build artifacts, complicated CI pipelines, and increased storage overhead.

Hiding UI chrome via client-side JavaScript after `window.onload` was also rejected. Post-mount DOM mutation causes visible flashes of unstyled content (FOUC) and jarring layout shifts.

To eliminate FOUC, a pre-boot script in the document `<head>` parses query and hash parameters synchronously before first paint. The script applies state attributes (`data-chrome="minimal"`, `data-inspector="off"`, `data-minimap="off"`) directly to `document.documentElement`. Declarative CSS selectors (`html[data-chrome="minimal"] .m-breadcrumbs, html[data-chrome="minimal"] .m-dock { display: none; }`) suppress extraneous controls instantly before content renders.

In addition, `@marrow/runtime` listens for `hashchange` events. Host pages embedding diagrams inside `<iframe>` containers can toggle chrome or theme states dynamically without reloading the iframe document.

## Consequences

**Single versatile artifact.** One generated HTML file serves as an interactive desktop tool, an embedded dashboard widget, or a clean kiosk display.

**Zero visual flash.** Declarative `<head>` attribute initialization prevents flashes of unstyled content and layout shifts during page load.

**Retained interactivity.** Minimal chrome hides navigation rails and breadcrumbs while keeping zoom, pan gestures, device selection, and tooltips fully interactive.

## Considered and rejected

**Separate embed build artifacts.** Rejected because maintaining multiple build flavors doubled compilation times and asset storage requirements.

**Asynchronous `postMessage` negotiation.** Rejected because asynchronous handshake messages cannot prevent the initial frame from painting full chrome before hiding it.

## Amendments (November 2026)

- **Parameters.** Alongside `chrome`, `inspector`, `minimap` and `theme`, the pre-boot
  script also applies `controls=on|off` (`data-controls`) and the runtime applies
  `d=<device-id>` and `c=<x>,<y>,<zoom>` deep links on boot. The `layout` parameter
  and `data-layout` attribute were removed; nothing read them.
- **What minimal chrome hides.** Command bar, breadcrumbs, sidebar, sidebar backdrop,
  watermark, minimap and the phone bottom bar. Zoom controls, pan, selection and
  tooltips stay live. Earlier builds left the bottom bar and the backdrop in place,
  which blurred Site pages on narrow viewports.
- **Flags survive.** The runtime rewrites only its own `d` and `c` hash keys and
  preserves every other pair, and links between the pages of a Site carry the
  active flags, so an embedded Site stays in kiosk mode as the viewer navigates.
- **Hooks.** The chrome elements the runtime looks up are `data-m` attributes
  defined by the page contract ([ADR-0023](/docs/decisions/0023-typed-page-contract)),
  not CSS classes; the CSS selectors in this record illustrate the mechanism only.
