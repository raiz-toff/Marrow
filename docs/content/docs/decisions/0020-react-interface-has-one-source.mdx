---
title: ADR-0020 — The React interface has one source
description: packages/ui/src is the only source of the React pieces; the shadcn registry is generated from it, and copied files stay self-contained by construction.
---

**Status:** accepted · amends [ADR-0019](/docs/decisions/0019-shadcn-registry-and-modular-ui-components)

`packages/ui/src` is the single source of `MarrowEmbed`, `CableBadge` and
`DeviceLink`. The shadcn registry (`registry.json`, `docs/public/r/**`) is
generated from those files by `scripts/build-registry.mjs`; nothing under
`registry/` is hand-maintained any more, and the directory is gone. The public
interface of `@marrow/ui` is exactly the three pieces named in ADR-0019 plus
`cn` and the `DeviceStatus` / `LinkMode` types.

## Why

The registry copy was a second source of truth. Three component files and a
519-line types file were committed twice, differing only in one import line,
and the build script read the *copy*. Every edit had to be made twice, and the
published `device-link` item was already broken: it imported `./cable-badge.js`
without shipping it. Meanwhile each `npx shadcn add` delivered roughly 500
lines of types and a mock topology (`TopologyData`, `DEFAULT_TOPOLOGY_DATA`)
that no component used, and four aliases of `MarrowEmbed` contradicted
ADR-0019's "exactly these pieces".

A shadcn registry distributes **source files that are copied into the
consumer's codebase**, so a copied file can never import `@marrow/*`. That is
why the `DeviceStatus` and `LinkMode` unions are declared as literals in
`packages/ui/src/lib/utils.ts` rather than imported from `@marrow/model`. The
duplication is deliberate and guarded: a test asserts they equal the model's
`DEVICE_STATUSES` / `LINK_MODES`, order included.

## Consequences

**One edit per piece.** Changing a component means editing one file; the
registry JSON is regenerated by `npm run registry:build` (part of `npm run
compile`).

**Self-containment is enforced, not hoped for.** The build fails on any
`@marrow/*` or `../` import in a component, and on any npm import that is not
`react`, `react-dom` or listed in the item's `dependencies`. Sibling
`./x.js` imports are pulled into the same item, which is what fixed
`device-link`.

**Smaller installs.** The shared types file shipped with every item went from
519 lines to 16.

**Narrower interface.** `TopologyCanvas`, `TopologyViewport`, `TopologyStage`
and `MarrowDiagram` no longer exist; use `MarrowEmbed`. The registry item id
`topology-canvas` and its URLs are unchanged.

**`marrow add` reads the root `registry.json`** and falls back to the docs
copy, so the CLI no longer depends on a docs build artifact.

## Considered and rejected

**Importing types from `@marrow/model` in the components.** Rejected because
the files are copied, not built; the import would break in every consumer.

**Keeping `registry/` as a generated, committed directory.** Rejected: a
committed copy invites hand edits, which is exactly how the drift started. The
generated JSON is committed because the docs site serves it statically.
